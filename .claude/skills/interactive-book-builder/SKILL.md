# Интерактивная книга из глав

Скилл описывает проверенную схему, по которой книга собирается из отдельных файлов глав,
а не пишется одним куском. Такая схема нужна, когда книгу правят и дополняют месяцами:
каждая глава живёт своим файлом, книгу можно пересобрать одной командой, а вставка новой
главы не ломает нумерацию.

Опыт взят из книги «ИИ-ферма для BSF» (13 глав, модальные окна, вставка глав, упаковка
для партнёров). Здесь — обобщённая версия, пригодная для любого проекта.

## Главная идея

Книга — это не монолит. Есть три слоя:

1. **Каркас** (`book/_shared/`): стили, движок окон и содержания, обложка. Один на всю книгу.
2. **Главы** (`book/chapter-NN/`): по файлу на главу. Внутри — только данные главы
   (JSON) и её модальные окна.
3. **Сборка** (`book/index.html`): генерируется из глав скриптом. Руками не правится.

Почему так: правка текста главы не требует трогать остальные 12 файлов, а оформление
меняется в одном месте и сразу во всех главах. Если сложить стили в каждую главу,
через полгода они разъедутся, и книга будет выглядеть по-разному в разных местах.

## Быстрый старт

```bash
node scripts/scaffold-book.js --dir "C:\Projects\MyProject" --title "Название книги" --subtitle "Подзаголовок" --chapters 3
node scripts/assemble-book.js --write --force
node scripts/package-book.js --name моя-книга
```

Получится:

```
MyProject/
  book/
    index.html          — книга (генерируется)
    _shared/            — shell.css, shell.js
    cover/              — cover.css, cover.js (обложка)
    chapter-01/glava.html + content.md
    chapter-02/...
  scripts/              — assemble-book.js, package-book.js
  dist/моя-книга/       — пакет для отправки + ZIP
```

## Ежедневная работа

### Править главу

1. Открыть `book/chapter-NN/glava.html` в браузере — это самостоятельная страница с обложкой,
   содержанием и окнами. Ровно так глава будет выглядеть в книге.
2. Править:
   - текст — в JSON-блоке `chapter-data`;
   - окна — между `<!-- CHAPTER-MODALS:START -->` и `<!-- CHAPTER-MODALS:END -->`;
   - статус и путь — в `content.md` рядом.
3. Пересобрать: `node scripts/assemble-book.js --write`.

### Добавить главу в конец

Создать папку `chapter-NN` из шаблона (или попросить агента), задать `order` больше всех
существующих, пересобрать.

### Вставить главу между существующими

Задать новой главе дробный `order`: между главой 3 (`order: 3`) и главой 4 (`order: 4`)
подойдёт `3.5`. Остальные файлы не меняются. В книге нумерация пересчитается сама:
новая глава станет 4-й, бывшая четвёртая — 5-й.

Если вставляют ещё одну между 3 и 3.5 — берётся `3.25`. Сборщик сортирует по числу,
повтор `order` считает ошибкой и останавливается, поэтому молча перепутать главы нельзя.

### Удалить главу

Удалить её папку и пересобрать. Предохранитель не даст случайно собрать книгу с меньшим
числом глав без флага `--force` — это защита от потери текста.

## Ключевые правила

- **Имена папок ничего не решают.** Порядок задаёт `order`. Поэтому папки не переименовываются
  при вставках. Имя папки — только для навигации человеком.
- **Номер в книге — позиция, а не `order`.** В оглавлении всегда 1, 2, 3… Дробные значения
  в книгу не попадают. В отдельном файле главы целый `order` показывается номером,
  дробный — без номера.
- **Ссылка на окно** ставится по вхождению `label` в текст тезиса:
  `{ "text": "... слово ...", "links": [{ "label": "слово", "modal": "exampleModal" }] }`.
  Если `label` в тексте нет — ссылка не появится (тихая ошибка, проверяйте глазами).
- **id окон уникальны на всю книгу.** Сборщик проверяет и падает при повторе.
- **Пути к изображениям в главах** — `../assets/...`; при сборке префикс убирается.
- **`index.html` руками не правим** — изменения затрутся при следующей сборке.

## Проверка перед публикацией

1. `node scripts/assemble-book.js` — dry run: список глав, порядок, предупреждения.
2. Синтаксис встроенных скриптов: открыть главу и книгу в браузере, пройти по ссылкам.
3. `node scripts/package-book.js --name ...` — собрать пакет.
4. Открыть `index.html` и `index-standalone.html`, нажать все ссылки-окна, проверить Esc.

Подробный чек-лист и способ автоматической проверки через headless Chrome — в
`references/verification.md`.

## Где что лежит в скилле

- `references/architecture.md` — формат файлов, схема JSON, маркеры, контракт движка.
  Читать перед первой правкой или при переносе книги на эту схему.
- `references/workflow.md` — пошаговые сценарии: новая книга, миграция старой книги,
  добавление/вставка/удаление главы, правка обложки, публикация.
- `references/pitfalls.md` — грабли, на которые уже наступали: локальные файлы и браузер,
  кодировки PowerShell, полоса прокрутки в окне, ZIP и картинки, встраивание base64.
- `references/verification.md` — как проверить книгу без ручного клика.
- `assets/templates/` — шаблоны: `index.html`, `chapter.html`, `shell.css`, `shell.js`, `cover/cover.css`, `cover/cover.js`.
- `scripts/` — `scaffold-book.js`, `assemble-book.js`, `package-book.js`.

## Перенос уже существующей книги

Если книга уже написана монолитом (одним `index.html` с массивом глав), переводить её
целиком за один раз не нужно:

1. Вынести каркас в `_shared` (стили, движок, обложка).
2. По одной главе: создать `chapter-NN`, перенести данные и окна, проверить в браузере.
3. Сборщик не даст собрать неполную книгу, пока глав в файлах меньше, чем в книге.
   Поэтому миграция безопасна: книга остаётся рабочей до последней главы.
4. После переноса всех глав — пересобрать.

Пошагово — в `references/workflow.md`, раздел «Миграция монолитной книги».

## Передача партнёрам

Скилл самодостаточен: скопируйте папку `interactive-book-builder` целиком в
`~/.claude/skills/` у партнёра (Windows: `C:\Users\<имя>\.claude\skills\`).
Ничего доустанавливать не нужно: скрипты на Node.js без зависимостей, шаблоны внутри.
